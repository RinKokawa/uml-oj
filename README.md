# UML OJ

**让 UML 建模像编程题一样可以提交、测试和评测。**

UML OJ 是一个面向软件建模学习与练习的在线评测系统。用户阅读中文业务需求，通过可视化画布或 UML 源码完成建模，再提交答案。系统将答案转换为统一的 UML 中间模型，运行题目定义的测试用例，并返回逐项测试结果与可解释反馈。

## 核心原则

- **测试用例驱动评测**：评测依据是题目要求及其测试用例，不是与唯一标准答案做图片或文本比较。
- **多种合理解法**：满足题目约束的不同模型都应有机会通过。
- **双输入方式**：支持结构化可视化绘图，也支持 PlantUML 等文本形式。
- **统一模型**：所有输入最终转换为统一的 UML 中间表示（UML IR），再交给同一套 Test Runner。
- **可解释结果**：显示每个测试用例的 PASS / FAIL、失败原因和相关模型元素。
- **确定性优先**：基础判分由可重复的规则测试完成；AI 可以辅助解释开放式语义，但不应成为基础客观判分的唯一依据。

## MVP 范围

第一阶段聚焦 **UML 类图**：

- 中文题目与题目说明
- 可视化类图编辑器
- PlantUML 源码输入与预览
- UML IR 转换与校验
- 测试用例 DSL 与 Test Runner
- 提交结果、逐项测试报告

暂不纳入第一阶段：自由手绘图片识别、多人协作、排行榜、复杂社交功能，以及所有 UML 图类型的完整支持。

## 当前可运行原型

当前仓库已包含一个浏览器端 MVP：

- 使用本地类图画布，无需在线 iframe。点击类或关联后，在右侧属性面板编辑；桌面可开启「专注画布」收起源码，属性面板并排显示。添加关联时先选起点再选终点，按 Esc 可取消。触屏上可以在画布空白处滑动查看超出视野的节点。
- 使用有限的 PlantUML／Mermaid 类图转换器；源码和画布均通过共同类图模型评测。
- 提供七个循序渐进的教学关卡：类、属性、普通关联、一对多，以及三个接口与接口方法练习；附知识讲解、操作步骤、补全模板和可展开的参考答案。
- 教学关卡只评测已学内容，通过后可进入下一关；桌面工作区同时展示题面、画布和源码，手机上切换画布与源码。
- 五道正式挑战：项目管理、图书借阅、独游雷达、装修验收、稿件批注。稿件批注既接受直接关联版本，也接受通过审阅记录关联版本。
- 提交后按题目要求检查类、接口、属性、接口方法名称、普通关联类型和两端多重性，并逐项显示 PASS / FAIL。
- 教学关卡和正式题库分别提供列表，选择具体题目后进入工作区；工作区可收起题面。
- 画布与 PlantUML／Mermaid 源码共享同一份答案；类的属性、方法和参数可逐项编辑，修改需点击“应用更改”。源码不完整或双方发生冲突时暂停同步和评测；面板存在未应用修改时也会阻止提交和切换，避免静默丢失。
- 默认使用暗色模式（包括可视化画布），可在右上角切换亮色。
- 应用界面和本地画布使用 Lucide 内联 SVG。
- 主题偏好、草稿、完成进度和当前答案的评测状态保存在本机浏览器的 localStorage，刷新可恢复；修改答案后需要重新评测。清除浏览器数据、换浏览器或存储不可用时可能丢失，不会同步到其他设备。尚未支持多标签页并发编辑，请勿在多个标签页同时修改同一道题；重要答案请下载备份。
- 可导出当前评测模型 JSON，或下载包含源码、模型、画布布局与未应用编辑的草稿 JSON。草稿 JSON 尚无自动导入功能。

### 本地运行

```bash
npm install
npm run dev
```

打开 Vite 输出的本地地址（默认 http://localhost:5173）。

### 当前原型边界

- 目前有七个教学关卡和五道综合类图练习，教学内容与测试数据定义在 `src/problems.ts`。
- 当前测试覆盖类及接口存在、指定属性及接口方法名称、普通关联类型和两端多重性；尚未验证方法参数或返回类型、导航方向、属性类型、可见性及复杂业务约束。
- 本地画布和源码支持有限类图子集：普通类、接口、属性和方法、普通关联及两端多重性。接口实现关系、继承、抽象类、自由图形和任意 draw.io 文件不在当前画布支持范围内。
- 评测在浏览器本地运行，尚无账户、服务端提交记录或题库管理后台。
- 提交前检查源码与画布语义一致，再由 `src/judge.ts` 将共同类图模型转为最小评测模型；尚未实现完整 UML IR schema 和测试 DSL。

### 源码与画布转换

画布、源码和评测使用 `src/uml/` 的共同类图模型及格式适配器：

- 源码 → 画布：支持英文标识符命名的普通类、接口、属性、方法、普通关联、关系名称及两端多重性；保留成员声明中的类型和可见性。
- 画布 → 源码：把上述模型转换成当前选择的 PlantUML 或 Mermaid。仅移动位置不改写原源码；修改类、成员或关系后会重新生成源码，此时注释、原排版和成员混排顺序不保证保留。
- 别名、枚举、包、任意注解、样式指令和关联端角色名等暂不支持转换；遇到这些内容会暂停同步和评测并保留两侧内容，不会仅挑选可识别元素后覆盖答案。
- 出现双方都已修改的冲突时，需要手动选择保留哪一侧；应用先将两侧内容备份到本机，再执行所选操作；若无法创建备份，不会覆盖内容。
- 转换器逐条读取有限语法，不支持完整 UML。

本原型用于验证“编辑器 + 测试用例 + 逐项判题”的核心体验，不应视为完整 UML 标准验证器。

### UML 适配模块（开发中）

`src/uml/` 定义 OJ 类图语义模型及 PlantUML、Mermaid 适配器；答题页使用本地画布，通过共同模型同步和评测。`src/uml/adapters/drawio.ts` 是历史实验代码，当前答题页不使用在线 draw.io，也不提供 draw.io 文件导入。Mermaid 只接受已实现和测试覆盖的有限类图写法；暂不能结构化编辑的已有成员声明以原文保留。

答案与进度使用 `uml-oj-native-drafts-v1`，布局和未应用编辑按题目分别使用 `uml-oj-native-layout-v1:<题目 ID>`、`uml-oj-native-pending-v1:<题目 ID>`。沿用此前本地画布的存储键和旧版未应用面板草稿；不自动读取或删除更早的 draw.io／Apollon 数据，也不导入独立原型的浏览器数据。冲突解决前会备份原内容。浏览器数据被清除或存储不可用时仍可能丢失；重要答案请及时下载备份。

### 验证

使用 Node.js 22.18+（CI 使用 Node.js 22）：

```bash
npm test
npm run build
npx playwright install chromium
npm run test:e2e
```

浏览器测试默认使用 `http://127.0.0.1:5186`，会自动启动开发服务。也可用 `PLAYWRIGHT_CHROMIUM_EXECUTABLE_PATH` 指定已安装的 Chromium 可执行文件。旧 draw.io 界面的浏览器测试保留在仓库中供参考，但因界面已移除而由 Playwright 配置排除；draw.io 适配器的单元测试仍运行。
