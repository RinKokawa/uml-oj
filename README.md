# UML OJ

**让 UML 建模像编程题一样可以提交、测试和评测。**

UML OJ 是一个面向软件建模学习与练习的在线评测系统。用户阅读中文业务需求，通过可视化画布或 UML 源码完成建模，再提交答案。系统将答案转换为统一的 UML 中间模型，运行题目定义的测试用例，并返回逐项测试结果与可解释反馈。

## 核心原则

- **测试用例驱动评测**：评测依据是题目要求及其测试用例，不是与唯一标准答案做图片或文本比较。
- **多种合理解法**：满足题目约束的不同模型都应有机会通过。
- **双输入方式**：支持结构化可视化绘图，也支持 PlantUML 等文本形式。
- **统一模型**：所有输入最终转换为统一的 UML 中间表示（UML IR），再交给同一套 Test Runner。
- **可解释结果**：显示每个测试用例的 PASS / FAIL、失败原因和相关模型元素。
- **确定性优先**：基础判分由可重复的规则测试完成；AI 可以辅助解释开放式语义，但不应成为基础客观判分的唯一依据。

## MVP 范围

第一阶段聚焦 **UML 类图**：

- 中文题目与题目说明
- 可视化类图编辑器
- PlantUML 源码输入与预览
- UML IR 转换与校验
- 测试用例 DSL 与 Test Runner
- 提交结果、逐项测试报告

暂不纳入第一阶段：自由手绘图片识别、多人协作、排行榜、复杂社交功能，以及所有 UML 图类型的完整支持。

## 当前可运行原型

当前仓库已包含一个浏览器端 MVP：

- 使用 Apollon（MIT）提供支持评测的可视化 UML 类图编辑器。
- 提供独立的 draw.io 试用画布：通过官方 `embed.diagrams.net` iframe 在线加载，须有网络。试用草稿以 `.drawio` XML 单独保存在当前浏览器，可手动下载备份；试用画布尚未接入评测、PlantUML 双向转换或原画布草稿，不会覆盖已有答案。切换题目、模式或主题前会请求当前画布快照，快照失败时留在试用画布。浏览器关闭或意外断网时，尚未自动保存的修改仍可能丢失，重要草稿请下载备份。
- 使用开源 `plantuml-parser` 解析 PlantUML 类图语法子集。
- 提供四个循序渐进的教学关卡：认识类、添加属性、普通关联、一对多；附知识讲解、操作步骤、补全模板和可展开的参考答案。
- 教学关卡只评测已学内容，通过后可进入下一关；默认从源码教学开始，也可以切换画布练习。
- 保留两道综合练习：项目管理系统（入门）、图书借阅系统（进阶）。
- 提交后检查类、属性、普通关联类型和两端多重性，并逐项显示 PASS / FAIL。
- 教学关卡和正式题库分别提供列表，选择具体题目后进入工作区；工作区可收起题面。
- 同一关卡的源码与画布可双向转换，切换时同步同一份答案。
- 默认使用暗色模式（包括可视化画布），可在右上角切换亮色。
- 界面图标统一使用 Lucide 内联 SVG（Vue 界面按需导入 `@lucide/vue`；Apollon 内置工具栏使用 Lucide React），不使用 Unicode 字符或图标字体代替图标。原生选项中的完成状态用文字表示，UML 语法和业务文本中的符号保持原样。
- 主题偏好、草稿和完成进度保存在本机浏览器的 localStorage，刷新可恢复；清除浏览器数据、换浏览器或存储不可用时可能丢失，不会同步到其他设备。建议重要答案导出备份。
- 可导出当前模型 JSON。

### 本地运行

```bash
npm install
npm run dev
```

打开 Vite 输出的本地地址（默认 http://localhost:5173）。

### 当前原型边界

- 目前有四个教学关卡和两道综合类图练习，教学内容与测试数据定义在 `src/problems.ts`。
- 当前测试覆盖类存在、指定属性存在、普通关联类型和两端多重性；尚未验证导航方向、属性类型、可见性及复杂业务约束。
- PlantUML 模式依赖 `plantuml-parser`，该项目声明尚未完整覆盖 PlantUML 全部语法；目前只适配类图中的类、成员和关系。
- 评测在浏览器本地运行，尚无账户、服务端提交记录或题库管理后台。
- 两种输入通过 `src/judge.ts` 转为最小评测模型；尚未实现完整 UML IR schema 和测试 DSL。
- 源码评测使用 `plantuml-parser` 的独立 PEG 语法模块，避免引入 Node.js 文件读取等 CLI 依赖。

### 源码与画布转换

`src/conversion.ts` 提供有明确边界的双向转换：

- 源码 → 画布：支持英文标识符命名的类、抽象类、属性、方法、普通关联、单向关联、继承、实现、依赖、聚合、组合、关系名称及两端多重性；保留成员声明中的类型和可见性。
- 画布 → 源码：把上述模型转换成可继续编辑的 PlantUML。仅移动位置不改写原源码；修改类、成员或关系后会重新生成源码，此时注释、原排版和成员混排顺序不保证保留。
- 更新源码后重新生成画布时，按同名类保留已有位置和节点 ID，新增类使用网格布局。
- 别名、接口、枚举、包、注解、构造型、样式指令和关联端角色名等暂不支持转换；遇到这些内容会明确阻止切换，停留在原模式并保留内容，不会仅挑选可识别元素后覆盖答案。
- 转换器逐条读取有限语法；它的支持范围比用于评测的第三方解析器更严格。

本原型用于验证“编辑器 + 测试用例 + 逐项判题”的核心体验，不应视为完整 UML 标准验证器。

### 验证

使用 Node.js 22.18+（CI 使用 Node.js 22）：

```bash
npm test
npm run build
npx playwright install chromium
npm run test:e2e
```

浏览器测试默认使用 `http://127.0.0.1:5186`，会自动启动开发服务。也可用 `PLAYWRIGHT_CHROMIUM_EXECUTABLE_PATH` 指定已安装的 Chromium 可执行文件。
